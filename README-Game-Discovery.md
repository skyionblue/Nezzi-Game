# Together Game Concept Workshop -- Discovery Guide

> **Purpose:** This document is designed to kick off collaborative
> discussions about building a polished iOS/Android puzzle game. Rather
> than immediately defining mechanics, we'll answer the right questions
> first so the game develops around a strong vision.

------------------------------------------------------------------------

# Elevator Pitch

**Working Concept**

Two characters with opposite strengths must work together to solve
puzzles. Neither can finish a level alone.

-   **Big** overcomes large obstacles.
-   **Little** overcomes small obstacles.
-   Every puzzle requires cooperation.
-   Success comes from combining their unique abilities.

------------------------------------------------------------------------

# The Design Philosophy

The goal is **not** to make "a game with two characters."

The goal is to make a game where **interdependence** is the core
mechanic.

Every obstacle should naturally ask the player:

> "Which character can solve this... and how does that solution help the
> other?"

The best puzzles should end with an "Aha!" moment.

# A Design Idea Worth Exploring

This is the idea that could become the game's signature.

Instead of designing puzzles around **Big** or **Little**, design them
around **interlocking solutions**.

Every obstacle should have **two halves**.

Example:

A massive stone blocks the path.

-   Big can push the stone.
-   Pushing it creates a narrow tunnel underneath.
-   Only Little fits through.
-   Little activates a switch.
-   That switch lowers a bridge Big can now cross.

Neither character "solved the puzzle."

**Together they solved it.**

That subtle difference changes how players think.

The player stops asking:

> "Which character is correct?"

and starts asking:

> "How do these two abilities connect?"

That is where memorable puzzle design lives.

------------------------------------------------------------------------

# Guiding Principle

Every puzzle should satisfy these four steps:

1.  Observe
2.  Understand each character's strengths
3.  Use one character to enable the other
4.  Celebrate the solution

If a puzzle can be completed by only one character, it probably needs
another design pass.

# Recommended Next Steps

1.  Finalize the game's vision.
2.  Name the characters.
3.  Decide on the visual style.
4.  Define the first 10 mechanics.
5.  Prototype 10 tutorial puzzles.
6.  Playtest early and often.
7.  Expand into a full Game Design Document (GDD).

> **Remember:** Great puzzle games aren't remembered because they had
> clever mechanics. They're remembered because they taught players to
> think differently. The opportunity here is to build every puzzle
> around cooperation, making "working together" not just the story, but
> the gameplay itself.
